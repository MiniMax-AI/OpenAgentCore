# Parsar Core 控制台

[English](README.md) | **简体中文**

Parsar Core 控制台（`apps/web`）是一套自部署 Parsar Core 的运维后台。应用用自己的密钥调用兼容 OpenAI 的 Agents API；运维在控制台里查看服务是否健康、容量是否够用、用量多少、哪里出错。业务协作属于 Parsar；凭据和执行始终在浏览器之外。

![Parsar Core 控制台总览](images/overview.png)

## 信息架构

| 分组 | 页面 | 用途 |
| --- | --- | --- |
| 监控 | 总览 | 服务状态、节点在线、沙箱槽位、运行中会话、需要处理的工作；左侧机群列表（Core 部署与每个节点），右侧显示所选对象的容量、主机资源、托管运行时用量和沙箱分配 |
| 监控 | 智能体监控 | 1 小时 / 6 小时 / 24 小时 / 7 天内的请求数（智能体 Turn）、错误率、平均与 P95 耗时、Token 和工具调用，按模型、工具和智能体拆分 |
| 监控 | 沙箱监控 | 节点容量表、托管运行时 CPU/内存/Token 历史和 Runtime 目标明细 |
| 监控 | 会话日志 | 全部会话的状态、模型、环境和 Token，可筛选，并在会话调试中打开 |
| 资源 | 智能体 | 以表格列出已保存的智能体及其用量：按状态统计的会话数，输入/输出/总计/缓存命中/推理 Token，用量覆盖率和最近活跃时间，可选全部、近 7 天或近 30 天；已删除或内联智能体的会话归入“其他 Agent” |
| 资源 | 环境模板、Skills、凭据库 | 完整展示的可复用托管配置、所有已上传的 Skill 及其版本、只写的 MCP 凭据 |
| 资源 | 文件 | 本项目的所有文件（包括通过 API 上传的）：上传、复制 File ID、确认后删除 |
| 基础设施 | 节点 | 添加、查看和移除执行节点 |
| 设置 | API 密钥、系统配置 | 签发和撤销 Agents API 密钥；查看 Core 构建与启动配置 |
| 调试台 | 会话调试、智能体构建器、新手引导 | 调试工具：与智能体对话、创建和编辑已保存的智能体、重放新手引导 |

页面使用同一套页头（标题、放说明的问号提示、操作）、同样的正文节奏、细线框表格与图表、状态圆点和容量条；说明文字收在问号里，不再铺成一行行小字。缺失的数据显示为缺失（—），不会显示成 0。

## 指标如何计算

Core 目前没有聚合接口，控制台用现有接口推算，并在页面上注明覆盖范围：

- 总览、会话日志和智能体页面在可见时每 30 秒重读完整会话列表和运行时观测。
- 智能体用量在打开页面或刷新时按创建时间倒序、每页 100 条读取会话列表，越过所选时间范围的起点即停止（会话按 `created_at` 归入范围）。用量是 Core 报告的每个会话的累计值，不按天拆分。没有报告用量的会话计入覆盖率，但不计入 Token 合计；会话都没有报告用量的智能体显示“无数据”，而不是 0。读取可以取消、失败后可以继续，结果只保存在当前页面内存中。
- 智能体监控读取所选时间范围内最多 200 个最近活跃会话的 Turn 与 Item，每个会话限时 15 秒、每次加载总预算 45 秒。一次请求即一个根智能体 Turn；耗时从 `started_at` 到 `completed_at`；错误率为失败 ÷ 已结束的 Turn；模型取自会话的智能体快照。不含子智能体 Turn 和已删除的会话；全部读取失败时页面会如实提示，而不是显示“没有运行”。
- 节点与分配数据来自仅供控制台使用的 `/core/v1/sandbox` 路由；托管 CPU/内存历史来自 Core 的运行时历史。

可以替代这些浏览器端计算的接口，见[管理员指标：后端需求](admin-metrics-backend-requirements.zh-CN.md)。

## 产品界面

### 总览

首屏回答四个问题：服务是否健康、容量是否够用、有多少在运行、什么需要处理。左侧机群列表第一项是 Core 部署；选中节点后显示它的槽位占用、主机 CPU/内存/磁盘、放置在该节点上的会话的托管运行时用量，以及沙箱分配。“需要处理”表列出失败的会话和等待必要操作的会话。

### 智能体监控

时间范围控件作用于页面上的所有数字。请求与错误按时间段堆叠，耗时显示平均值和 P95；Token、模型、工具三段各有一个分布图和一个趋势图。每个模型或工具在可见期间保持同一种颜色，每张图都能展开数据表；标题旁的问号说明数字如何得出，会话上限或分页上限导致数据不完整时会显示“部分数据”标记。

![智能体监控](images/agent-metrics.png)

### 沙箱监控

节点容量表列出每个节点的上限、用量、主机资源和最近心跳。下方的托管运行时历史保留 Core 周期观测得到的 CPU、内存和 Token；Web 不直接连接数据库，也不接收监控凭据。提供方只报告累计 CPU 时间时，Web 只在同一个已验证的 Runtime 实例的相邻采样之间推算区间利用率。

### 会话日志与会话调试

会话日志是可搜索的记录。打开某个会话会进入会话调试，那里保存该会话在 Core 中的对话、追踪、工具活动和后续输入。

### 智能体与智能体构建器

智能体页面是清单。编辑、创建、启动测试会话都在调试台的智能体构建器里完成。

### 环境模板

在启用托管环境的构建中，打开**环境模板**查看所有可复用配置，包括通过 API 创建的模板。模板详情展示网络模式和允许访问的域名、npm/Python/系统依赖包、能力目录、文件（内联文件的大小或 File ID，可跳转到“文件”页）、Skill（ID 或名称，以及默认、`latest` 或指定版本，可跳转到 Skills 页）和 Plugin。环境变量和启动命令属于机密配置，Core 不返回它们，所以控制台看不到模板是否配置了它们。含有控制台无法识别的配置的模板会被标记，只显示能识别的部分，并且不影响其他模板。

控制台只创建和编辑模板的名称与网络（包括带域名列表的 `restricted` 模式）；更新请求只包含这两个字段，其他配置保持不变。删除前需要确认，已创建的 Session 不受影响。保存模板不会启动 Runtime，也不会调用模型；无论配置多复杂，模板都可以在新建托管 Session 时选用。

### 文件

**文件**列出本项目的所有文件（包括通过 Files API 上传的），显示名称、大小、创建时间、purpose 和 File ID，每次加载 100 个，可按最新或最早排序。可以上传不超过 512 MiB 的文件（允许空文件），并复制 File ID 在模板中引用。上传或删除没有得到明确结果时，控制台不会自动重试，请先刷新列表确认。删除文件不影响已复制到 Session 工作区的副本和已创建的 Session，但引用它的模板之后再新建 Session 会失败。

已知限制：Core 没有文件搜索接口，筛选只作用于已加载的行；用户数据文件不能下载，因为 Core 会拒绝读取其内容。

### Skills

**Skills** 列出本项目的所有 Skill（包括通过 API 上传的），以及它们的默认版本、最新版本、创建时间和 ID。可以上传一个 ZIP 或文件夹，其中唯一的顶层文件夹里要有 `SKILL.md`；发送前，对话框会预览文件夹名、文件数、大小，以及 frontmatter 里的 name 和 description。在 Skill 详情页可以上传新版本（可选设为默认）、切换默认版本、下载默认版本或指定版本，以及删除版本或整个 Skill。已有的 Session 保留创建时的 Skill 内容。

已知限制：Core 没有 Skill 搜索接口，筛选只作用于已加载的行；Core 不记录上传者；浏览器中的检查只是辅助，最终以 Core 的校验为准。所连接的 Core 没有 Skills API 时不显示入口；Core 未配置 Skill 存储时，页面会给出说明。暂不支持在环境模板中挂载 Skill。

### 系统配置与连接状态

系统配置展示所连接 Core 的构建支持项，以及本次进程启动时的配置：执行引擎、daemon 网关、自托管执行、托管沙箱提供方和运维模型端点是否已配置。配置不会被当作模型执行已就绪。

只有所连接的 Core 和 Web 运维配置明确暴露的能力才会显示。

## 快速开始

### 环境要求

- Node.js 22.12+
- pnpm 10.30.3
- 一个正在运行的[兼容 Agent Core](#兼容的-core)
- 由 Core 运维方签发的调用方密钥

### 启动 Web

```bash
git clone https://github.com/MiniMax-AI/parsar-core.git
cd parsar-core
pnpm install
cp .env.example .env.local
pnpm dev:web
```

开发服务器默认使用 `http://127.0.0.1:4173`，并把浏览器请求代理到
`http://127.0.0.1:8091` 的 Core。

在 `.env.local` 中配置本地代理：

```dotenv
AGENTS_API_PROXY_TARGET=http://127.0.0.1:8091
AGENTS_API_PROXY_TOKEN_FILE=/absolute/private/path/to/web-token
```

只有本地 Web 服务会读取调用方密钥文件。不要把明文密钥放进 `VITE_*` 变量、URL、
截图、Agent、Session metadata 或 Git。

### 第一个工作流

1. 打开**调试台 → 智能体构建器**，选择**创建智能体**。
2. 设置名称、模型和指令，只在需要时添加支持的工具。
3. 选择**启动会话**，选择环境，并可同时发送第一条消息。
4. 在**会话调试**中继续工作，查看实时事件和持久化历史；随后在**总览**和**智能体监控**里看到这次运行。

## 本地 Core 与 Docker

Web 无法访问本地 Core 时，Dashboard 会打开连接引导，提供两条路径：

- **这台电脑已经配置过**：启动已配置的数据库、Core API 和 daemon 容器，验证
  `/healthz`，然后运行 **Test connection**。
- **这台电脑第一次使用**：构建 Core 镜像，并按照当前仓库内的文档创建数据库、
  调用方身份、迁移、API 容器和 daemon profile。

可使用 [`.env.example`](../../.env.example) 中的非秘密配置启用本地恢复引导。Web 只展示
经过校验的命令，不会获得 Docker socket、执行命令、创建凭据或猜测数据库身份。

完整步骤参见[连接 Agent Core](core-connection.md)。启动 daemon 可能释放已排队工作
并产生模型用量，操作前应先检查待处理 Session。

## 兼容的 Core

Agents Core Web 使用[协议覆盖范围](protocol-coverage.md)中经过测试的
`/v1/agents/**` HTTP 和 SSE 契约。

| Core | 状态 |
| --- | --- |
| [`0000a0b` 的 Parsar Core](https://github.com/MiniMax-AI/parsar-core/tree/0000a0b32523deb0f7a4d907f31ca4503cff7e9e) | 仓库内主要集成 |
| 实现了已记录子集的其他 Core | 完成契约验收后兼容 |
| OpenAI 托管 Agents API | 不承诺完全兼容 |
| OpenAI Agents SDK、Responses API 或 Parsar daemon WebSocket | 属于不同接口，不能作为 Core 地址直接连接 |

浏览器只连接 Core。鉴权、持久化 Agent/Session 状态、调度、执行和运行时资源都由 Core
负责；浏览器不会直接连接 daemon 或模型提供商。
