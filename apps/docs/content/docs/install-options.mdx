Pass options to the downloaded script:

```sh
./install.sh --host 127.0.0.1 --port 8088
```

With the Quick start pipeline, append `-s --` and the options after `bash`.
The release downloader also accepts `--version TAG` to select a published release;
otherwise it selects the latest stable release.

## Process settings

These flags seed the installation's `config.json` once. Their defaults, valid values
and restart behavior are defined in the [configuration reference](/configure#settings).
After installation, edit that file and run `oac apply`; rerunning the installer
repairs the same version and accepts only `--install-dir`.


| Flag | config.json field |
| --- | --- |
| `--core-only` or `--web-only` | `mode` |
| `--native-core` | `native_core` |
| `--public-url` | `public_url` |
| `--host` | `host` |
| `--core-port` | `ports.core` |
| `--port` | `ports.web` |
| `--core-url` | `web.core_url` |


`--config FILE` seeds `config.json` from a JSON file instead of these setting flags;
they cannot be combined. There is no precedence between two configuration sources.
Generated Compose and environment files are derived outputs, not editable settings.

## Listeners and access

`--host` sets the IP address on which Core and Web listen. It accepts IPv4 or IPv6,
without a port, URL scheme or IPv6 zone. `--port` changes Web's port;
`--core-port` changes Core's API port. PostgreSQL remains private.

A listener address selects a network interface; `--public-url` selects the canonical
address that browsers, API clients, nodes and Runtime use. Non-loopback listeners,
including `0.0.0.0` and `::`, require an HTTPS public URL and the
[reverse proxy configuration](/install#https-and-the-reverse-proxy).
Point the reverse proxy at the chosen listeners. Wildcard addresses are bind targets,
not browser URLs. Changing the listener does not provide TLS or change authentication.

## Installation actions

These options choose an installation location or perform initial setup. They do not
create another process configuration file.

| Option | Purpose |
| --- | --- |
| `--install-dir DIR` | Absolute installation directory; defaults to `~/.oac/core`. A new installation requires an empty or missing directory |
| `--sandbox docker\|microsandbox\|e2b\|none` | Select the initial [sandbox backend](/install#sandbox-backend), saved in Core's database; change it later in Web |
| `--accept-docker-risks` | Accept Docker's weaker isolation without an interactive prompt |
| `--e2b-api-key-file FILE` | With E2B: absolute path to a private key file, no group/other access and at most 4 KiB |
| `--e2b-template ID:BUILD` | With E2B: ready template build as `template-id:build-uuid` |
| `--core-key-file FILE` | With Web-only: absolute path to a private file containing the existing Core key, at least 32 characters |

See [deployment modes](/install#modes), [native Core](/install#native-core) and
[sandbox setup](/install#sandbox-backend) for their prerequisites.
Several installations can share a machine when they use distinct installation
directories and ports. Each has its own database, Core key and node registrations.
